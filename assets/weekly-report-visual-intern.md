# 视觉设计实习生周报

## 一、任务识别

| 触发词 | 执行动作 |
| --- | --- |
| 周报、weekly report、本周总结、实习记录 | 执行本 skill |
| 有草稿内容粘贴 | 执行「三、有草稿流程」 |
| 仅说\"帮我写第 N 周周报\"无草稿 | 执行「四、无草稿流程」 |

---

## 二、固定报告结构

每周周报统一输出以下结构，不随意增减章节：

```
第 N 周
[日期范围，如 2026.06.09 - 2026.06.12]

一、工作总结

| 成长性 | 待改进 |
| --- | --- |
| 1. [成长点标题] | 1. [待改进点标题] |
| [一句话说明] | [一句话说明] |
| 2. [成长点标题] | 2. [待改进点标题] |
| [一句话说明] | [一句话说明] |

💡 工作小结
[2-3 句话，总结本周核心成果 + 后续改进方向]
```

**字段说明：**
- 成长性：本周有实质进展的工作模块，每条含标题 + 一句话进展描述
- 待改进：本周暴露的薄弱环节，每条含标题 + 一句话描述问题现象
- 每栏固定 2 条，保持对称
- 工作小结：不超过 3 句，不写空话，需点出具体项目名称或技能

---

## 三、有草稿流程

1. **读取草稿**：读取用户粘贴的原始内容
2. **识别信息**：提取成长点、待改进点、小结关键句，识别缺漏
3. **整理输出**：
   - 原有表述**保留核心意思，润色语言**，不替换专业词（如 PAG、序列帧、酷小狗、酷狗、AI agent）
   - 若草稿缺少某栏条目，补充占位提示 `[待补充]`，不自行编造
   - 保持双栏对称结构，按「二、固定报告结构」输出
4. **同步生成可视化卡片**：调用前端组件渲染周报卡片（参考既有样式：左列绿点「成长性」、右列橙点「待改进」、底部绿色左边框「工作小结」）

---

## 四、无草稿流程

1. **确认信息**：询问用户以下内容（一次性列出，不分多轮）
   - 第几周 + 日期范围
   - 本周做了哪些工作（关键词或事项均可）
   - 觉得哪些做得好 / 哪些还不够
2. **生成草稿**：根据用户回复，套入「二、固定报告结构」生成
3. **输出**：同步生成 Markdown 文本 + 可视化卡片

---

## 五、写作质量标准

### 内容层面

- **成长性要写出\"做了什么 → 有何提升\"**，不只写动作
  - 差：`参与了改版设计`
  - 好：`参与酷狗页面改版设计，对版式排布与交互逻辑认知有进一步提高`
- **待改进要写出\"现象 + 方向\"**，不写泛泛的\"有待提升\"
  - 差：`网格系统有待提升`
  - 好：`页面排版规整度不足，字号、分区板块标准化有待完善`
- **工作小结要点名项目**：必须出现具体项目名（如\"酷狗 AI agent 形象动画\"），不写\"本周完成了各项工作\"之类空话
- 专业术语原样保留：PAG、序列帧、AE、Figma、酷小狗、AI agent、TME 等不转译

### 语言层面

- 简洁、主动语态，每条描述不超过 30 字
- 同一项目名称前后用词一致（\"酷狗\"不混用\"kugou\"）
- 不使用\"积极\"、\"努力\"、\"不断\"等模糊形容词

### 结构层面

- 成长性与待改进严格对称（各 2 条）
- 小结不超过 3 句，第 1 句写成果，第 2 句写联动/进展，第 3 句写后续方向
